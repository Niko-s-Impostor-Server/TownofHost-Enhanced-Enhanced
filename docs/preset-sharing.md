# 本地预设保存与分享

房主在大厅输入 `/save 名称`，将当前模组选项写入
`TOHE-DATA/Presets/名称.preset`。将这个文件交给另一位使用相同模组版本和
Among Us 2026.8.18 的房主，对方放入自己的同一路径后输入 `/load 名称`。
名称可以带 `.preset` 后缀，也支持中文、字母、数字、空格、`-` 和 `_`，
长度为 1–64 个字符。路径、其他扩展名和 Windows 设备名会被拒绝。
`/save` 会以临时文件和替换操作更新同名文件；没有文件的 `/load` 不会新建文件。

这两个命令只处理执行房主电脑上的文件，只有本地房主能执行；远程玩家、
授权管理员、开发者身份均不能通过聊天让房主执行文件操作。
游戏中以及启动过渡阶段不能保存或导入。

## 导入范围

文件包含当前预设槽位的全部可编辑模组选项，也包含 `scope: "global"`
标记的全局模组选项。当前分支有部分职业设置存放在全局选项中，因此它们也会
随文件导入。全局设置会影响所有预设槽位；`scope: "preset"` 的设置只写入
导入时房主正在使用的槽位。当前预设编号、其他槽位、标题行以及原版游戏选项
不会从文件恢复。`sourcePreset` 是来源信息，不能切换目标槽位。

布尔值记录选项自身的开关值，父项关闭时仍能保留子项开启的设置。
`name` 和 `choices` 使用稳定的内部名称，避免分享文件依赖翻译语言。

## JSON 格式与校验

`.preset` 是缩进 JSON，格式编号为 1，同时记录选项存储格式编号、游戏版本和
完整模组版本。导入要求这些版本与当前程序完全一致，要求可编辑选项集完整且
与当前选项的 ID、名称、类型、作用范围、数值规则和候选项顺序一致。
旧版本或另一个模组的文件需由对应版本导出，不能自动混入当前配置。

每项包括 `index`（内部存储索引）和 `value`（可读值）。二者必须匹配：
布尔值只能是 JSON 布尔类型，整数只能是整数，浮点值必须对应指定步长的有效
索引，选择项必须等于该索引的内部名称。手工修改时需要同时修改 `index` 和
`value`，不能更改规则字段来扩展范围。

未知、重复、缺失的 ID，重复 JSON 属性，多余字段，类型错误，越界索引，
不匹配的值，版本错误以及超过 2 MiB 的文件都会在修改任何设置前被拒绝。
导入失败不会改写输入文件，也不会广播部分结果。

通过校验后，服务批量修改内存值，使用 `OptionSaver.TrySave()` 原子替换
`TOHE-DATA/SaveData/Options.json`，成功后只调用一次已有的设置同步接口。
应用或持久化失败时恢复内存快照；持久化成功后的传输异常只记录日志，
已经提交的设置仍然生效。网络同步效果需要实际游戏客户端验证。

## 集成与离线验证

聊天命令的本地路径调用 `PresetSharing.Save(name)` 或
`PresetSharing.Load(name)`。结果的 `Success`、`FileName`、`OptionCount`
可用于显示成功消息；错误的 `TranslationKey` 是 `PresetSharing` 加上
`Error` 枚举名称。聊天命令的远程接收路径必须直接拒绝这两个命令，服务本身
再次检查房主身份和大厅状态。服务不能从 `AmongUsClient.AmHost` 推断聊天发送者。

执行 `dotnet run --project tests/PresetSharing/PresetSharing.csproj`。
测试项目直接编译真实的预设服务、选项类和持久化模块；使用模拟的游戏/UI
边界验证导出/导入、独立槽位、全局设置、关闭父项下的布尔值、完整输入校验、
读写权限、文件大小限制、磁盘提交失败的回滚以及 UI 更新异常的回滚。
这些测试没有启动游戏，也不证明实际多人 RPC 或游戏界面同步。
