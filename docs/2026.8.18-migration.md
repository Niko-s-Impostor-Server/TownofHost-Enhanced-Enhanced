# Among Us 2026.8.18 migration

## Baseline

This branch starts at the released TOHE **v2.1.1**, commit
`3676f644e39612b8fe7ea6ddfd0b46a643f08dba` (2024-11-03). It was built against
AmongUs.GameLibs.Steam **2024.10.29** and advertised support for
2024.8.13, 2024.9.4 and 2024.10.29.

The commit immediately before the first RateLimit-related change was already
2.2.0 Beta 2.1, not a stable release. The original checkout is preserved on
`codex/pre-20260818-backup-20261004`; this migration is on `codex/au-20260818`.
No remote history has been rewritten.

The target is the Windows **IL2CPP Itch** build of Among Us 2026.8.18 with
BepInEx 6.0.0-be.755 and Il2CppInterop 1.5.1. Its decompiled protocol constants
are 2026.7.15. The application version and protocol version are different data.
This branch is intended for private servers.

## Build

Use a .NET 8 or newer SDK. Run the target game with BepInEx once to generate
its interop assemblies, then build against that exact installation:

```powershell
dotnet build TOHE.csproj -c Release -p:LocalAmongUsPath='D:\Game\20260818\Itch'
```

`LocalAmongUsPath` only supplies references; it does not deploy anything.
The output is `bin/Release/net6.0/TOHE.dll`. Copy only that DLL to the game's
`BepInEx/plugins` folder while the game is stopped. Do not distribute or copy
the referenced game/BepInEx assemblies as plugin dependencies.

The NuGet fallback targets GameLibs 2026.8.18; the local installation build is
the validation reference. Costura/Fody is no longer needed. Dotfuscator
configuration and obfuscation attributes disappeared with the baseline reset.

## Main changes

- GameOptions V11 and the game's own option serialization factory.
- New typed voting IDs and complete ClearVote/VotingComplete payloads.
- Current game-end enums, role lookups, map icons and Harmony signatures.
- Removed old network-stream replacements and the obsolete disconnect penalty
  patch. The current game's native batching and spawn flow run normally.
- Removed the retired TOHE API, embedded API token, cloud connector and login
  integration. Announcements use embedded resources. Upstream auto-update is
  disabled so it cannot replace this fork with an incompatible binary.
- Options handle malformed persistence data, normalize preset arrays, save via
  temporary replacement, and avoid duplicate save/sync callbacks.
- Settings menus own their construction state, cancel stale coroutines, avoid
  duplicate help icons and rebuild controller navigation after construction.
  Non-host clients cannot edit host settings.
- Role timer callbacks validate their lifetime and targets. Fireworker's HUD
  cannot publish authoritative state from a non-host client.
- Session callbacks are bounded and canceled when the connection, room generation,
  player identity or host changes. Rejected RPCs cannot reach the Harmony postfix.
- Pelican and Shroud clean up only their own targets, including when their owner
  object has disappeared. Their cleanup wire IDs are appended without renumbering.
- FreePlay initializes mod state after native tutorial player/task allocation.
  Its 325 selectable roles and add-ons use native folders with at most six items
  per directory/page. Switching and closing release old role and UI ownership.
- Initial host role assignment also informs Nmpostor of the host's own role.
  Intro callbacks check room lifetime and current host authority. The obsolete
  patch that skipped native player-data readiness waits has been removed.
- Task totals are initialized after native task installation. Task completion
  only awards role progress for an installed, still-pending task ID. Personal
  role progress remains separate from shared task-win eligibility.
- Task-panel text is invalidated after FreePlay role changes, including taskless
  roles. Game-end translations use the current native enum names in all 16 languages.
- Option backups skip the native read-only `Roles` boolean instead of writing it
  back during each sync. Role-rate backups include all ten V11 special roles.
- Delayed un-shapeshift setup validates the session, host, round and captured
  player/role instances. Stale callbacks neither send RPCs to replacement players
  nor remove their registrations. Periodic cleanup iterates a snapshot safely.

## Verification

```powershell
dotnet run --project tests/Infrastructure/Infrastructure.csproj -c Release
dotnet run --project tests/RoleLifecycle/RoleLifecycle.csproj -c Release
dotnet run --project tests/SessionLifecycle/SessionLifecycle.csproj -c Release
dotnet run --project tests/TaskLifecycle/TaskLifecycle.csproj -c Release
```

Infrastructure tests link production sources and stub game dependencies. Role
lifecycle tests extract named production methods and run them against controlled
state. See the test README for the exact boundary. Neither proves all roles or
multiplayer gameplay.

Infrastructure's native boolean-contract checks also require Python 3 and the
provided 2026.8.18 decompiled source. Set `TOHE_NATIVE_SOURCE` to that source root
if it is not at the local default `D:\SharedUserFiles\TestDesktop\opencode-chat\assembly-compare\src-2026.8.18`.
The generated source stays under ignored `obj`; it is not committed. These tests
exercise the actual native Normal/HnS boolean getter/setter bodies with isolated
fixtures, alongside the production option backup code.

The local installation build succeeds. Offline harness results are 60
infrastructure checks, 54 role-lifecycle checks, 90 session-lifecycle assertions
and 32 task-lifecycle assertions.
These counts are not counts of fully tested playable roles.

All validation results reported here use the supplied Itch executable and installation.
Startup testing found and fixed early Dleks option access and an IL2CPP-injected
managed-enum registration error. The retired API's HTTP/JSON failures and login
gate have been removed.

Runtime checks completed in the actual game:

- Main menu startup and local host lobby creation.
- All seven visible mod setting tabs: 2,236 controls, unique ownership, controller
  navigation, hidden-control exclusion, 290 role-help buttons initialized three
  times, interrupted tab construction, close during construction, and reopening
  with fresh owners. Two complete passes had no new Error/Fatal log entries.
- System and crewmate settings screenshots visually inspected at 1100x650.
- FreePlay: seven players initialized, native four local tasks and six taskless
  dummies preserved. All 325 entries traversed on 55 role pages and 12 directories;
  hitboxes/render bounds checked against the viewport. Two owner lifetimes passed
  with no new errors. CrewmateTOHE/EngineerTOHE switching, checkmarks, old role
  removal and restoration passed. This does not exercise every role's ability.
- Native FreePlay pages contain six supported crew roles and three impostor
  roles. Attempts to select native Detective/Viper/Judge were rejected without
  changing role instances, tasks or UI/controller state. Visible native Engineer
  and Crewmate switching still passed. This sequence had no new Error/Fatal entries.
- 25 representative roles activated through the native TaskAdder. Each passed
  native/custom role agreement, old-role cleanup, five actual HUD updates and a
  matching task-panel heading in both source text and TMP's parsed display. This
  verifies activation and display, not the roles' individual abilities.
- Two separate Itch LocalGame instances joined and started a complete round.
  Both players received roles and six tasks, saw the intro finish and could move.
  The shared task total was 12. A non-host native task completion callback changed
  personal progress to 1/6 and shared progress to 1/12 on both instances.
- A non-host native emergency request reached the host. Both clients selected
  Skip and Confirm through the native button handlers, observed two Skip votes
  and zero player votes, and returned to gameplay without an ejection. Only the
  host clicked LocalGame's normal Proceed button. These cover request/result
  integration, not task-minigame input or walking to the emergency console.
- After the option-backup fix, a fresh two-instance round and Skip meeting passed
  again. The host's complete fresh-run Unity log contained zero occurrences of
  the previously repeated `could not set bool named Roles` error.

`tests/RuntimeSmoke` is a separate, temporary BepInEx test plugin, excluded from
the product build. Its fixed commands call native game UI entry points. Computer
Use window capture repeatedly timed out after approximately five seconds, so
these checks are not claimed as mouse/keyboard end-to-end tests. Unity captures
were used for visual inspection. The temporary NoGameEnd test option was restored
without saving. Runtime logs also include EOS/storage, controller-menu messages
during programmatic scene transitions, and multi-instance LAN discovery errors.
Those messages were not isolated against an unmodified client; the complete run
is not represented as error-free.

After the earlier migration tests, the original BepInEx configuration, UnlockAllSkins and UnityExplorer
were restored. RuntimeSmoke was moved out of both plugin directories into local
test backups. A final cold launch without RuntimeSmoke initialized TOHE and both
original extra plugins and reached the native main menu, with no TOHE Error/Fatal
log entries. All test game processes were then stopped.
The second Itch test directory is retained for further isolated validation.

## RPC, abilities and inline follow-up (2026-10-05)

- All active custom send sites now use the native message queue with outer RPC
  123, int32 recipient owner ID, fixed uint32 inner ID and immutable payload. Only the
  registered concrete TOHERpcMessage enters IL2CPP; no custom packetizer was
  reintroduced. See [rpc123.md](rpc123.md).
- Removed console-detach/hiding paths and obsolete Last* cooldown configuration.
  Lobby cooldown values are backed up untouched; after Started the host sends
  cloned per-player initial options before assigning roles. Actual LAN tests
  preserved the original 19-second KCD backup.
- Keeper, Cleanser, Eraser, Oracle and FortuneTeller implement a shared meeting
  ability interface. Compatible clients use native Judge selection independently
  of votes, with host validation, replay/context checks and owner-local rearming.
  Unmodded or different-build clients retain the legacy vote path. See
  [meeting-abilities.md](meeting-abilities.md).
- Disperser uses a shared Phantom ability API on matching modded clients. The
  non-host sends the native owned CheckVanish request; the host adjudicates the
  cooldown/effect and broadcasts visible StartAppear. Unmodded owners retain the
  Shapeshifter base. Transporter keeps its existing task-triggered gameplay.
- Compared 267 patch declarations (228 unique targets) against the site's
  same-date Steam x86 dataset. All five former stripped comparison targets were
  migrated to substantive lifecycle/state callers; 23 potentially-inline
  declarations remain documented, rather than being blindly removed. The site
  has no Itch dataset. See [il2cpp-patch-audit.md](il2cpp-patch-audit.md).
- Removed the new empty RoleBehaviour.AdjustTasks hook after it caused startup
  trampoline failures. Subsequent cold starts reached the main menu without
  those failures. Dleks map icons now copy data, not the whole GameStartManager.
- HUD status placement uses safe-area, actual toolbar/task/meeting bounds and
  rendered text dimensions. Stable layout probes are limited to 10 Hz; unchanged
  bounds reuse the cached layout. Game screenshots at 1000x600 and 1280x720 show
  the version/ping/server block clear of the notes/settings/map buttons. A
  1000x600 meeting capture was also inspected. These are native Unity captures,
  because Windows Computer Use capture again timed out.

Two Itch LAN clients completed matching-version handshake, fixed Keeper/Disperser
assignment, intro and movement. The non-host's actual Phantom ability handler
teleported both players to vents, stayed visible without fade/role animations,
and started cooldown without task changes. The host's native Judge selection
consumed one Keeper use (3 to 2), preserving votes/tasks/emergency count with an
empty native overrule queue. Both native Skip handlers returned to gameplay.
The original helper incorrectly demanded that opening an emergency meeting not
consume an emergency; this was corrected to require exactly one native charge.
The client helper also now compares deserialized TaskInfo by wire Id/Complete,
since native Deserialize reconstructs these objects; host task identity and
native task object/step checks remain strict. A subsequent two-client round
passed both post-meeting native-base and task-baseline checks (the client
observed 12 value-preserving TaskInfo replacements). One meeting-open
observation exceeded its eight-second stage budget; the subsequent native
Judge and Skip observations completed successfully without resending that
emergency request.

All focused offline harnesses pass: Infrastructure 60, TaskLifecycle 32,

See [host-only-commands.md](host-only-commands.md) and
[mod-registration.md](mod-registration.md) for syntax, identity and server boundaries.
The fixed internal version `2026.1005.211.1` derives
`d15f9333-446f-5203-aab4-4b09191bc94e`. Native LocalGame/FreePlay hosting suspends
only our registration for the synchronous HostGame call, because the native LAN
server accepts tag 0 but not tag 25; online hosting retains registration.

The full Release build and actual-interop lifecycle compile passed with zero
warnings/errors. New offline suites pass 145 command-path assertions and 47
registration assertions. The refreshed inline inventory has 268 declarations /
229 unique targets; the same platform-comparison limits still apply.

Both installed modded Itch clients cold-started to MainMenu with matching runtime
GUIDs and no Error/Fatal startup lines, then created/joined the native loopback
LAN lobby. The host snapshot confirmed the GUID was restored after local hosting.

The final paired eight-second `/cmd id` LAN observation passed on both clients.
The sender invoked native ChatController.SendChat once, emitted one Reliable
SendChat RPC to HostId and displayed one native private response. The host
observed one envelope receipt/consumption, one existing `/id` dispatch and one
response addressed to that sender. Both sides observed zero command displays,
public replies, replay calls or unexpected routes. All five host/eight sender
observer hooks were removed with zero cleanup failures. The first attempt had
non-overlapping observation windows and a test-only bulk-unpatch exception; the

NikoCN accepted a fresh private online room while the registration remained set.

The second native modded client again timed out before joining. Both helpers
reported leaving/restoring their original regions. This is registration/hosting
evidence, not online multiplayer or proof that untagged server events had no flags.
No server commands, services, configuration or log files were modified.

The requested additional configuration is **two TOHEE clients plus one genuinely
vanilla client**, with at most three game processes. A separate
`Itch-Codex-Vanilla` installation was copied from the supplied Itch native files

The mixed-client follow-up must verify actual private-room admission, vanilla

excluding vanilla clients; Nmpostor reference source's registration and listing
filter support alone do not prove its deployed direct-join admission rule.

## 2026-10-05 lobby preview, templates and settings-list follow-up

The lobby settings preview was restored using the original `7d7a47dea` /
`9e51c20c6` behavior as reference. One HUD-owned text object shows cached options,
with immediate privacy invalidation and a 0.5-second probe for other changes.
TMP measurement paginates the final width/font with space reserved for the
Tab/number-key footer. Chat and native overlays hide it; HUD/lobby destruction
disposes it. The status layout also treats this text as an obstacle.

The shipped Simplified Chinese welcome title was missing `>` after its color
attribute. The default resource is fixed; the existing TemplateManager parser
repairs that exact old title in memory without migrating the user's file. It
also fixes title/body extraction when a title block has a nonzero offset.
There is no separate production TemplateMessage class or Chinese parser.

The reported CreateSettings coroutine exception originates inside native
List.Add. A diagnostic run found valid backing arrays for both constructor
overloads and did not reproduce the reported failure, so a universal broken or
inlined parameterless constructor is **not established**. The fix initializes
a fresh, positive-capacity Children list at CreateSettings itself, clears a
prior partial build, and retains that owned list throughout the coroutine.
It no longer depends on the Initialize prefix/template list being the only
entry path. The template uses a positive-capacity empty list too.

Validation on the supplied Itch installation, one owned local host:

- Cold-start native settings test after the list change: two complete passes
  over all seven mod tabs (2,236 controls per pass), a third owner closed during
  construction, interrupted tab construction/resumption, help icon repeated
  initialization, owner/registry cleanup and reopen all passed, error delta 0.
  Each completed tab additionally checks native Children backing storage.
- Native lobby pagination/return, singleton text, chat hide/restore passed;
  nine pages were generated for the existing configuration.
- The actual existing welcome template passed native parsed-title, absence of
  literal color markup, nonoverlapping title/body bounds and player-name
  restoration checks. Native captures were inspected; the tall welcome bubble
  scrolls outside the visible chat viewport, so bounds checks are not a claim
  that its entire contents fit onscreen simultaneously.
- Offline: template/resource 14 assertions, preview formatter/pagination 15,
  GUI lifecycle 17. Main and runtime helper compile successfully. Inline audit:
  293 attributes / 271 targets, no unresolved declarations; the Steam dataset
  remains comparison-only for this Itch build.

Computer Use window capture still returned `FrameArrived timed out`; native
test-plugin entrypoints, layout observations and Unity screenshots provided
the runtime evidence. This is not end-to-end mouse/keyboard coverage, nor does
it cover the pending two-mod-plus-one-vanilla online scenario.
