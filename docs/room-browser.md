# Room browser UI (AU 2026.8.18 Itch)

`ServerDropdown.FillServerOptions` runs native pool creation, ordering, translations and `ChooseOption` listeners. Its prefix clears the otherwise accumulating controller list, and its postfix arranges that exact list into columns before native `OnEnable` opens the overlay. The native selected-region `firstOption` stays intact. Background geometry, dropdown position and scale are saved for an open and restored after native `OnDisable` reclaims the buttons/closes the overlay. Expanded dropdowns are fitted inside the current orthographic camera, with uniform scaling only when their background exceeds the available view.

`FindAGameManager.Start` prefix checks the target's uniformly spaced single-column, shared-parent prefab. Before native reset, More-event registration and `ControllerManager.NewScene`, it adds enough native `GameContainer` clones to reach ten slots. Clones keep their native click bindings; their buttons join the native controller list and use automatic navigation instead of copied explicit links. Any native explicit bottom-row Down link is extended only while the first added row is active; smaller responses restore its original target. The viewport has a finite collider derived from original serialized box-collider corners, including inactive prefab rows, and a separate, movable `Scroller.Inner`. Its drag surface sits behind all original card buttons/colliders in native depth order; a counter-offset keeps the cards at their original z. It inherits the page's intro animation and destruction because it remains under the original parent.

`HandleList` prefix clears stale cards for both HTTP and UDP responses. Native `HandleList` still shuffles and populates supported listings with options using the expanded array. The postfix uses the resulting cards, not response-array indices, to update the added display text and reset the actual active-row scroll range. `TrueHostName` falls back to `HostName` (native UDP `DeserializeV2` does not populate `TrueHostName`). Native `GameCode.IntToGameName` selects the valid V1/V2 conversion. Remote names are bounded plain text with line-control characters removed; the label has `richText=false`. The existing `gameListing`, IP, port, ID, permissions, filter sets, chat restrictions and join/More calls are untouched.

The host/code label clones the native capacity TMP font/material, uses the capacity-column and native tag-row anchors, and allows ellipsis/autosizing. A page-owned coroutine suppresses offscreen card renderers and mouse colliders while retaining enabled UiElements for native controller navigation. When controller selection enters an offscreen card, that card is revealed; joystick mode also keeps the current selection visible after switching back from mouse scrolling. The native viewport's wheel/drag behavior remains in charge of movement. Whole-card culling avoids text/sprites spilling over controls without a global black overlay. Native `OnDestroy` removes the owner's managed state and stops its coroutine; Unity destroys its child viewport/rows/labels. No custom IL2CPP MonoBehaviour registration or global scroller is needed.

The reference commits are `ceae88295`, `a07955922`, `9982e43da`, and local `upstream/main`. Their static scroller, `Inner` pointing to itself, 100-by-100 collider, hardcoded fifth row and z=25, black cover, and scene-name split are not reused. The separate unsupported mod-filter TODO is outside this feature.

Offline validation: `dotnet run --project tests/RoomBrowser/RoomBrowser.csproj` checks the production layout/text helper for hundreds of region counts, reachability of row ten, smaller/empty responses, controller reveal bounds and remote name handling. Coordinated main-project compilation checks the generated Itch interop API. All new native hooks have nonempty target-source bodies; the cached same-version Steam analysis marks FillServerOptions, OnDisable, Start, HandleList and OnDestroy `matched`, with no inline tag. Steam metadata is comparison evidence, not proof of Itch detour behavior. Empty/inlined `SetGameListing` and icon methods are not patched.

No game is launched or deployed by this change. Exact prefab geometry/label placement, wheel/drag input, controller navigation, repeated open/close, HTTP/UDP response behavior, native hook execution and connecting to a listed room still need a game-client smoke test. The UI cannot show more rooms than the server returns; ten slots do not increase a server-side response limit.
